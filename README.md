# RoutePic

걸어온 길을 AI가 해석해 그림으로 남기는 iOS 앱.

```
이동 기록          경로 → 형상            AI 해석·생성           기록·공유
──────────      ─────────────         ─────────────        ─────────────
GPS 폴리라인  →  단순화·정규화     →   무엇처럼 보이나(VLM)  →  카드 렌더
              →  컨트롤 이미지      →   형상 구속 생성        →  피드/컬렉션
              →  형상 지문                                   →  공유
```

## 어려운 지점은 AI 생성이 아니다

임의의 GPS 경로는 대체로 아무것도 닮지 않았다. 계획해서 달린 경로는 이미 고양이 모양이지만,
어제 퇴근길은 그냥 꺾인 선이다. 그래서 이 앱의 성패는 이미지 생성 API를 붙이는 데 있지 않고
**"안 닮은 모양을 무엇으로 만들 것인가"** 라는 제품 결정에 달려 있다.

시장 조사에서 유사물을 찾지 못했다. 기존 앱은 전부 역방향(모양을 먼저 정하고 그에 맞는 경로를
계획)이거나, 순방향이어도 선을 예쁘게 꾸미는 데 그친다. 그건 기회이자 경고다 — 아무도 안 하는
이유가 "안 되어서"일 가능성을 설계서 §4와 §7.11이 정면으로 다룬다.

**축은 하나다. 구속을 올리면 기괴해지고, 내리면 내 경로가 아니게 된다.** 파이프라인을 2단으로
나눠도 이 트레이드오프는 사라지지 않는다. 스위트스팟이 넓어질 뿐이다.

## 실측이 설계를 뒤집은 것

문서를 읽거나 코드를 써서가 아니라 실제로 이미지를 만들어 보고 드러났다. 근거는
[`OnDevice/SPIKE-RESULTS.md`](OnDevice/SPIKE-RESULTS.md).

**아래의 신뢰도는 고르지 않다.** 라벨은 그 문서가 붙여둔 것을 그대로 옮겼다. 표본이 작고, 비블라인드
단일 판정이며, 조건들이 동일 seed 집합 위에서 교차되지 않았다. 확정으로 읽으면 SP-1 설계가 편향된다.

| 발견 | 라벨 | 내용 |
|---|---|---|
| **셀당 seed 1개로는 조건 차이와 생성 노이즈가 안 갈린다** | `[조사확인]` | 모든 스파이크가 셀당 seed 1개를 전제했는데, 그러면 아무것도 구분하지 못한다. 조건당 seed ≥ 5로 개정 — 통계적 임계가 아니라 운영상 스크리닝 규칙이다. **seed 분산이 조건 분산보다 크다는 주장은 아니다**(교차 설계가 아니었다) |
| **이 조합에서는 귀속감이 먼저 무너졌다** | `[가설]` | 경로 1개·프롬프트 1개·스타일 1개·seed 6에서 인식성 5~6/6, 경로 귀속감 0/6. Wilson 95% 구간이 각각 44–97%, 상한 39%라 순위를 매길 수 없다. 인식성을 게이트로 두되 실패율과 구간을 함께 본다 |
| **스타일 프리셋이 결과의 성격을 바꿀 수 있다** | `[가설]` | 라인아트는 경로를 추적하고 주제를 거의 만들지 않으며, 플랫 벡터는 그 반대로 보였다. 5건·비교차·비블라인드라 교호작용의 증명이 아니라 **교차 설계를 해야 할 이유** |
| **강도 축은 단조가 아니다** | `[조사확인]` | 42셀 전수에서 `edgeToRoute`가 2.6에서 최소를 찍고 되돌아왔고, 그 지점은 이미 그림이 죽어 있다. 준비한 지표는 이 축을 서열화하지 못했다 |

초판 결론은 셀당 seed 1개로 6건을 돌려 "구불구불한 경로엔 동물이 안 나온다"였다. seed를 6개로
늘리자 뒤집혔다. **이 개정 자체가 한 번 틀렸다**는 기록을 설계서에 남겨 두었다.

## 어떻게 측정하나

"실루엣이 경로를 따라간다"는 주장이 아니라 측정 대상이다.

| 척도 | 방법 | 상태 |
|---|---|---|
| 경로 귀속감 | 경로 선 오버레이 없이 "이게 내 경로 같은가" | 예비 0/6 `[가설]` — 병목으로 보이는 쪽 |
| 형상 충실도 | 결과에서 주 실루엣을 추출해 원 폴리라인과 대칭 Chamfer 거리, 그리고 P95 (Hausdorff 대용) | 강도 튜닝용. **귀속감의 대리 지표로는 실패했다** |
| 인식성 | 블라인드 평가자에게 이미지만 보여주고 자유응답 | 예비 5~6/6 `[가설]` — 하한 통과 조건 |
| 만족도 | 5점 척도 + 재생성 의향 | 미측정 |

단일 순위 척도로 만들지 않는다. 귀속감만으로 줄 세우면 충실하지만 보기 싫은 결과가 이기고,
평균은 사용자가 매 생성에서 겪는 실패율을 가린다. 셋의 파레토로 결정하고, 게이트에는 수치 임계와
신뢰 규칙을 사전 정의한다 — **임계 없는 게이트는 게이트가 아니다.**

채점에서 사람 눈을 뺄 수 있는 부분은 뺐다. `ShapeFidelity`가 거리 지표를 계산하고, 16장을 따로
열어 보지 않도록 `ContactSheetRenderer`가 한 장의 그리드 이미지로 묶는다. 다만 **기계 지표로 사람
평가를 대체하려던 시도는 실패했다** — `edgeToRoute`는 눈으로 성공한 샘플과 실패한 샘플을 구분하지
못했다. 평가자가 필요한 것은 예산 문제가 아니라 원리 문제다.

## 구조

| 모듈 | 역할 |
|---|---|
| `ShapeKit` | 투영·정규화·형상 지문, 컨트롤 이미지와 컨택트 시트 렌더 |
| `RouteKit` | 위치 수집, 필터 체인, 기록 모드, 세션 저널 |
| `GenerationKit` | 생성 클라이언트, 잡, 쿼터 원장, 온디바이스 경로 |
| `RoutePicStore` | 스키마, 활동 리포지토리, 아트워크 저장, 카드 렌더 |
| `Server/proxy` | 생성 API 프록시 |

서버 경로와 온디바이스 경로는 같은 transport seam 뒤에 있고, 온디바이스는 과금 대상이 아니라
쿼터 예약·확정·환불을 통째로 건너뛴다.

**온디바이스 경로는 붙었고, 서버 경로는 없다.** `CoreMLImageGenerator`가
[`ml-stable-diffusion`](https://github.com/apple/ml-stable-diffusion) 위에서 돌고 앱 타깃이
`GenerationKit`을 링크한다. 서버 팔은 여전히 `GenerationTransport`의 HTTP 구현체가 없다 —
온디바이스로 충분한지 판정(P2)이 나기 전에 만들면 낭비다.

**다만 이 체크아웃에서 그림이 나온 적은 없다.** 변환된 Core ML 팩은 1~2 GB라 저장소에도 앱
번들에도 없고, 받아올 서버도 없다 — 경로가 기기를 떠나지 않는다는 것과 같은 선택이다. Mac에서
변환해 Files로 넣고 설정에서 고르면 된다 (`OnDevice/README.md`). **팩 없이 파이프라인이 실제로
그림을 만든 적은 없다.**

Swift 76파일, 테스트 298개 통과 (ShapeKit 115 · RouteKit 75 · Generation 72 · Store 36).

## 상태

작업 중이다. `ShapeKit`·`RouteKit`·`RoutePicStore`·`GenerationKit`이 모두 앱에서 돌지만,
생성은 모델 팩이 있어야 실행된다(위 참조). 스파이크 2회가 끝났으나 제품 가설(SP-1)은 검증되지
않았다 — 평가자 없이는 원리적으로 불가능한 부분이 남아 있다. 설계서에서 `[가설]`과 `[미검증]`이
붙은 항목이 남은 리스크다.
